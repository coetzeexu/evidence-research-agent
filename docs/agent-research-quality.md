# Agent 调研方法与验收

目标是让 Agent 围绕研究问题自主调查、计算、质疑与补证，给出有依据、有边界、可复核的文字结论。使用 LangChain / LangGraph，正文研究与文件导出分别验证。架构见[设计说明](design.md)，实际运行结果统一见[运行验收](final-evaluation.md)。

## 质量目标

| 目标       | 验收条件                                                             |
| ---------- | -------------------------------------------------------------------- |
| 回答完整   | 明确要求与必要研究问题逐项有回答、依据和状态，不能用事件数量代替覆盖 |
| 证据可信   | 重要事实定位原文；推断说明依据、竞争性解释与局限                     |
| 数值可靠   | 数字由确定性指标生成；比较区间、频率、币种、费用、执行口径一致       |
| 分析有价值 | 说明观察、风险代价、适用条件及可改变判断的新证据                     |
| 自主有界   | 按问题补查、重算和改写；最多 15 分钟实际执行；缺证据准确标记缺口     |
| 可复核     | 保存问题—证据—指标—结论—核验链，以及版本、用量和执行记录             |

正常数据条件下两个主场景完整回答必答问题。不能证明因果时，可以形成有依据的有限结论；用户明确要求的事实缺失时，不能仅用宽泛讨论替代。

## 实现方法

```text
研究计划 → 数据采集与调查 → 确定性分析 → 结论草稿
  → 独立核验 → 定向补查 / 重算 / 改写 → 发布正文
```

主管维护问题、优先级、完成条件与预算；研究子 Agent 按问题获取支持证据、反证和竞争性解释；核验子 Agent 在独立上下文核对原文、指标、时间和措辞。工具承担数据读取与确定性计算，技能约定调查步骤、错误边界与停止条件。

`ResearchBundle.research` 包含研究问题、证据片段、指标、结论和逐轮核验。原文片段保留定位、哈希、时间和来源关系；结论区分事实、分析和假设。旧 Bundle 缺少该记录时为 `unassessed`。

首次研究与追问共用发布门禁。正文数字使用指标引用，程序定位比较片段并执行关系求值；核验器转录问题在核验侧修复，不要求作者改写正确结论。显式缺口跨补丁、恢复和完成判定保留，关闭必须有已批准且可定位的回答依据。未经核验的草稿不进入正文或聊天历史。

结论门禁之后，独立 `question-review` 仅根据已核验段落判断必答完成度。它将研究局限与额外方法分开，不要求有限事件研究证明独立因果，也不要求已有 CPI 回顾分析额外证明稳定机制；用户明确要求的事实与必要计算仍须回答，缺失不能靠免责声明关闭。

指标前缀规范化只接受精确存在的 ID，幅度关系使用明确的绝对值运算。旧问题状态不继承为完成依据；无效精确补丁在同一次修复内最多重试一次，记录错误并保留已核验结果。这些正文协议改进使用版本 `1.3`，计算方法 `2026.09.4` 未变。

## 研究口径

**事件与行情。** 分别记录发生、已核实公开、报道和市场反应时间。回顾报道日期不能替代历史公开时间。精确时刻按交易日历对齐；仅日期时检查当日与下一交易日窗口。时序吻合仅建立候选关联，结合机制、同期事件和基准走势解释，分别表达方向、反应强度和证据可信度。

**资产比较。** 组合与单资产使用共同锚点、相同区间、费用和执行引擎。正文纳入回测、实际购买力、压力期和敏感性结果，分别回答避险、抗通胀和配置问题。GLD 明确为黄金 ETF 代理，CPI 关联和历史分组仅支持相应样本的回顾性分析。

## 预算与接口

- 完整研究最多 900 秒实际执行时间，排队不计；720 秒后停止调查，预留综合与核验时间。
- 最多两轮检索补查、两轮正文修复；全程最多 34 次搜索、50 次原文读取、64 次模型调用；恢复沿用预算。
- 到期只发布已核验内容与缺口；没有可发布内容时返回失败。
- SSE 展示真实工具动作、问题与来源进展；核验正文发布后保留 `accepted / delta / done / error` 兼容协议。
- 追问基于当前研究快照，限制 180 秒；涉及新增数据或范围时转为新研究。
- `GET /api/runs/{id}/research` 与 CLI `research show` 查看文字；`export_reports` 持久化控制文件生成，完成度独立于导出状态。

## 验收设计

八次真实研究固定请求、日期、配置和生产版本：NVDA 与 GLD/BTC 各连续三次，AMD 与 GLD/ETH 各一次。每次保留正文、Bundle、证据片段、指标、核验结果、实际模型、Prompt / 技能哈希、耗时和用量。验收要求八次运行通过，不存在必答覆盖、引用、数值、窗口、口径或发布状态等基础错误。

检查分三层：程序独立重算与契约验证；生产核验上下文以外的重点结论复核；本机浏览器验证会话发起、过程中流式更新、完成正文和产物生成。固定版本运行结果见[运行验收](final-evaluation.md)，自动化命令见[验证记录](validation.md)。

完整验收只计入相同版本的八个独立端到端运行，并检查规定场景数量和必要检查项。`evaluate_saved_research.py` 复用既有证据做开发定向复验，不能替代完整运行；重复运行记录、缺检查项或混合版本也不能拼入八次通过。

故障回归覆盖盘后公告、日期不明、回顾报道、来源冲突、重复转载、数据缺失、口径混用、提示注入、预算到期恢复和草稿泄漏。每项明确应通过、应修复或应保留缺口，不能只检查程序没有抛异常。

## 工程方法

采用“保存真实片段 → 最小修复 → 定向重放 → 完整流程验收”。已落实同口径基线、核验后发布、片段 ID 数值核验、缺口持久化、精确补丁、结构化输出协议和版本记录。代码修复与模型选择分别归因，工程基础错误由可复现输入和回归验证。

[基线文字](../evals/text-baseline/)和[运行记录](../evals/text-research/)保留原始快照，不手工改写结果。文档描述当前能力与验证方法，阶段性调试结果由其原始记录承载。
