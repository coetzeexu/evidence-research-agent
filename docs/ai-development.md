# AI 辅助开发与人工决策记录

用户确定研究目标、交互要求、运行条件和验收标准，Codex 负责技术方案、代码、测试与文档。产品运行时另使用 LangChain / LangGraph Agent 调用用户配置的模型，完成问题拆解、调查、提取和核验。开发辅助 AI 与产品内研究 Agent 的职责分开记录。

## 使用的 AI 与工程工具

- **Codex**：阅读既有代码与真实输出，设计契约、编辑源码、编写回归、执行终端/API/CLI 检查并整理文档。
- **产品 Agent**：LangChain / LangGraph 主管及研究、核验上下文，使用受限工具与版本化 Prompt / skills。
- **Gemini review**：由用户提供的外部工程建议，经对照代码与运行约束后采纳，不将建议本身当作验证证据。
- **工程工具**：pytest、Ruff、Vitest、TypeScript、Prettier、构建工具、GitHub Actions、样例校验脚本及 LibreOffice 独立重算。
- **浏览器与协作**：在用户明确授权的阶段操作本地页面；当前验收使用开发子 Agent 分工。此前文字强化阶段仅用终端、API 和结构化记录。

模型密钥仅在服务端 `.env`，不写入 Prompt、前端、样例或仓库。网关实际返回过 `/workspace/model`，部署别名与返回标识分别保留，不能仅凭通用返回标识确认底层模型家族。模型配置由用户提供，兼容层修改和功能验证由 Codex 完成。

## 开发方法

先用可运行的垂直切片打通真实数据与 SDK，再共用数据契约完成计算、会话和多格式导出。研究强化阶段采用“冻结实际输入与输出 → 找出可复现边界 → 最小修复 → 定向重放 → 完整流程验收”。

单元测试用独立预期值和财务不变量；集成测试检查引用、状态、恢复与文件结构；真实模型评估独立于离线测试；浏览器验收检查用户看到的行为。运行记录保存事实，不手工改写 Agent 输出或通过状态。

## 关键实现与修改

| 实测问题                                     | 修改与验证方式                                                           |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| 长检索难以收束、恢复后预算可能重置           | 持久化执行与调用预算，调查/提取分阶段，补查和正文修复分别有上限          |
| 回顾文章日期、更新日期与历史事件时间混用     | 分离发生/公开/报道/反应时间，保留日期引文，按交易日历对齐                |
| 新闻相关卡片污染正文，失败 URL 重复读取      | 正文区域选择、发布元数据提取、按源失败计数与替代检索                     |
| 最终解释直接发布，绕过证据检查               | 初次研究与追问共用结构化草稿、独立核验和发布门禁                         |
| 单资产价格回顾与含费用组合直接比较           | 同锚点、同区间、同费用和同执行引擎的单资产基线                           |
| 数值关系误转录被交给作者反复改写             | 程序片段 ID 回填原句，专用转录修复，确定性关系求值                       |
| 占位符携带字面前缀、幅度比较被当作带符号关系 | 仅精确存在的 ID 可规范化；新增 abs 比较与原顺序序列运算，保留反例检查    |
| 初稿缺口在补丁或完成判定中丢失               | 缺口跨轮持久化，关闭需已批准且可定位的回答                               |
| 完成度审核混入额外研究方法要求               | 增加独立 question-review，只用已核验段落核对原要求，明确事实缺口继续阻断 |
| 整段修复保留旧错误再追加相反解释             | 精确 old/new 补丁，只修改失败结论，重新核验整个条目                      |
| 精确补丁定位失配直接终止修复                 | 同轮最多重试一次，将无效补丁与具体原因传回并落盘，持续消耗原预算         |
| 旧 answered 问题清单挤掉本轮有效 partial     | 初始化问题状态，完成状态仅从匹配输入哈希的 assessment 恢复               |
| 网关忽略结构化输出函数选择                   | 只接受完整且通过 Pydantic 模式的 JSON，拒绝猜测性提取                    |
| 旧提取阶段未复用统一结构化调用协议           | 共用函数选择、JSON 校验、诊断与预算；回归验证原文、旧事件及补查上下文    |
| 提取局部调用上限中断已有研究                 | 保存旧事件和原文，明确记录未收敛缺口并进入核验，不伪装补证成功           |
| 可改写问题与可选来源缺口同时触发重复调查     | 先做本地修复再核对必答覆盖；纯粹的必要证据缺失仍补查                     |
| 并行工具争用固定临时文件                     | 唯一临时文件原子替换，问题记录有序读改写                                 |
| 历史样例缺少新增字段                         | canonical Bundle 迁移、replay 重导出、跨文件一致性断言                   |
| 数据源由业务节点直接实例化                   | 按行情/资讯/宏观能力注入，支持受信服务端插件                             |
| 下载后的离线 HTML 因 Node 环境引用空白         | 明确生产构建变量，检查实际编译 JS，并由本机浏览器打开 file:// 文件验证   |
| 失败尝试计数与研究缺口混在结果区               | 过程记录保留；结果区展示具体待核实问题和可展开的数据说明，不改核验状态 |

历史片段留在 `evals/` 用于回归和比较；当前功能与验证结果以 [README](../README.md)、[设计说明](design.md)、[验证记录](validation.md) 为入口。

## Prompt 与技能

| 阶段     | 主要文件与作用                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------------- |
| 规划     | `prompts/planner.md`：资产、区间、任务类型与必答问题；额外要求绑定用户原话                                  |
| 调查     | `researcher.md`、`extractor.md`：搜索、读取原文、提取日期与证据；按具体缺口补查                             |
| 事件核验 | `reviewer.md`、`review-format.md`：独立证据判定与结构化结果提取                                             |
| 正文     | `synthesis.md`：事实/分析/假设分离，指标引用、反证和局限                                                    |
| 正文核验 | `text-reviewer.md`、`meaning-review.md`：引用/数值与推断边界分别审查                                        |
| 完成度   | `question-review.md`：只根据已核验段落核对必答要求，区分事实缺失、研究局限和额外方法                        |
| 数值转录 | `numeric-review.md`：选择程序片段 ID 与明确运算，不改正文和事实判定                                         |
| 修复     | `text-repair.md`：精确修复失败条目，保留已批准内容                                                          |
| 研究方法 | `skills/event-study`、`asset-comparison`、`evidence-review`、`report-authoring`：输入、方法、边界与停止条件 |

Prompt 与技能内容随代码交付，哈希写入运行记录。工具轨迹只展示允许的公开动作与来源，不把模型隐藏推理作为交付物。

## 本轮验收准备

根据用户要求，Codex 先复验真实运行暴露的工程边界，再冻结代码与 Prompt 启动完整八次研究。开发子 Agent 补充数值协议、完成度权限、旧状态恢复和补丁重试的反例回归；主 Agent 处理生产修复并执行开发快照复验。浏览器子 Agent 按授权检查本机发起会话、过程中更新和产物路径，文档协作独立进行。

结构化提取和本地修复优先级的修改来自真实失败快照。Codex 将提取器接入共享调用协议，开发子 Agent 分别验证上下文保留、局部预算、本地修复与缺证补查的分流，以及耗尽提取次数后的证据保留。定向快照验证只用于确认协议边界，最终研究结果仍使用冻结版本重新运行。

`tools/evaluate_saved_research.py` 仅复用保存的行情、原文及原请求重新执行正文流程，用于定位确定性边界；它会调用模型，但不重新调查，记录明确标为 `saved-evidence-development-probe`。这种定向复验不计入完整八次。正式结果以独立端到端运行和统一版本记录为准，不能从重复运行、不同版本或缺检查项凑出通过。

正文核验的 `verification_version` 更新为 `1.3`，行情、回测和敏感性计算方法仍为 `2026.09.4`。协议修复与计算方法变更分别记录；不将本轮调整描述为新金融模型。

## 交付与验证记录

工程复核包含数值关系定向重放、缺口回归、两套样例重导出，以及后端/前端测试和真实 GitHub CI。完整八次研究和本机浏览器的版本、结果、耗时与范围统一在[运行验收](final-evaluation.md)记录；命令和证据索引见[验证记录](validation.md)。

开发子 Agent 的协作与产品内部 SDK 子 Agent 分开：前者按用户授权承担本轮开发验收任务，后者属于交付代码的研究工作流。未使用当前请求未指定的设计类技能。

阶段收尾：按用户要求限制修复面，只补临时来源读取重试、离线 HTML 运行时和提示展示。最终移除各 tab 重复的“研究范围与依据”公共面板及专属旧测试，正文待核实事项仍保留。八次固定版本研究和浏览器实测分别留证，不把后续传输/UI 补丁冒充原八次运行版本。模型表述差异作为效果观察保存，不开启新一轮 Prompt 优化。
