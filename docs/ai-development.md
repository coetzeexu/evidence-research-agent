## AI 参与的工程步骤

1. 依据用户确定的场景和约束，整理评分维度、共同数据契约、时序与证据要求，提出技术方案；在用户确认整体架构与 ECharts 后落实实现。
2. 对免费 Yahoo、HN、FRED、新闻原文与模型工具调用做真实可行性验证，据实调整实现。
3. 编写领域模型、LangGraph 状态流、SDK 主 Agent / 子 Agent、工具白名单和可版本化技能。
4. 编写确定性分析、跨市场锚点、事件窗口、费用台账与 Excel 同口径公式。
5. 编写 React 工作台、Chat、可复用 ECharts 和单文件离线报告，加入 CSP 与服务端安全边界。
6. 生成 Office 样例，检查原生结构、重新计算公式、渲染逐页检查；按实际失败修复。
7. 使用用户提供的模型配置执行真实语义评估（初始 20 条，接续扩充至 22 条），并执行独立数值、安全和文件测试；保留各阶段结果，不虚报浏览器验证。

## 实测发现与修改

| 发现                                           | 调整                                                              |
| ---------------------------------------------- | ----------------------------------------------------------------- |
| 长检索任务达到图步数上限，无法收束             | 采用 SDK 模型调用预算，检索与结构化提取分阶段，修复最多两轮       |
| 新闻网站把相关文章卡片也标为 article           | 根据正文长度选内容区，保留文章 header 中的日期，拒绝过短页面      |
| 搜索服务结果为空或仅返回网站首页               | 保留失败轨迹；增加 HN 窄时间窗、免费 RSS、公开来源定位目录        |
| LLM 核验把 5 日方向与 1 日方向混淆             | 传入明确窗口定义、计算指标、实际截止日，新增方向窗口字段          |
| 只按来源 ID 存在判断，仍可能收录未核实事件     | 追加日期精度过滤，独立核验事实支持，移除严重问题的派生标注        |
| FRED 对自定义 User-Agent 超时                  | 对该固定接口使用 HTTP 客户端标准头，保持 TLS 校验，按源做兼容处理 |
| 初始交易费未计入月度累计收益分母               | 统一以初始资本计算总收益和回撤，增加恒定价格收费回归测试          |
| 不同资产共用事件时，详情可能显示另一资产的反应 | 列表按当前标的匹配，证据面板分别列出各资产窗口                    |
| DOCX 渲染中文缺失                              | 修正字体主题覆盖，并为本地 QA 配置现有中文字体，不修改系统字体    |

源码中没有写死 NVDA 或 GLD/BTC 的价格、收益、影响等级或事件结果。来源定位目录仅含可核验 URL；示例研究事实位于样例快照。该目录偏向验收主题，完全陌生的行业仍取决于公开来源可用性，不能承诺同等新闻覆盖。

## 验证方法

真实失败驱动的工程调整：

| 观察到的失败 | 实施修复与验证原则 |
| --- | --- |
| 原 explain 绕过核验，出现无依据预期解释 | 统一首次研究与追问门禁，禁止草稿发布；保留原始文字作为回归基线 |
| 单资产价格回顾与含费用组合直接比较 | 同一执行引擎重算单资产基线，逐项核对区间/费用/锚点 |
| 模型判“组合收益居中”，实际收益最高 | 把定性数值关系转为可执行断言，程序否决错误关系 |
| 新关系转录误把指标列举当相等、反转下降方向 | 记录误拦截，明确区分陈列、比较与序列；不以删除检查解决 |
| planner 自行加下行捕获率、回归显著性等验收要求 | 额外问题逐字绑定用户原话，保留用户明确要求，禁止自行扩写 |
| SDK 并行工具争用固定 `.tmp` 文件 | 唯一临时文件原子替换；问题记录串行读改写，并发回归 |
| 争议复核扩查无关数值耗尽调用 | 收窄争议上下文、分离工具和结果提取；中断保留原严重缺陷 |
| 部分自动检查通过，但独立阅读仍发现错误 | 该轮内容验收判失败，不算最终八次验收通过 |
