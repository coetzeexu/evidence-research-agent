# 从出题者角度设计评分框架

总分 100，先检查最低交付门槛：可运行代码、两个完整场景、至少两类真实数据、可打开产物、无密钥泄漏。门槛未满足时，不因演示外观好看而掩盖核心缺失。

| ---------------- | ---: | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |

等级建议：90 分以上要求六维无明显短板；75–89 分允许覆盖或工程细节存在限制但主链路可靠；60–74 分是局部可用原型；60 分以下通常存在核心场景缺失或数据可信度问题。评分应以真实运行和文件复核为准，不能仅靠自述。

建议现场验收顺序：

1. 离线打开样例，核验一条事件的来源和一个回测公式。
2. 新建研究，确认发送前没有未命名记录；模板填入后可修改，发送后进入实际研究会话。
3. 替换资产执行，观察公开文字增量、工具状态、来源和实际步骤；测试手动折叠、向上阅读暂停跟随、切换会话时迟到回复隔离。
4. 切换会话与报告，检查圆角工作区、固定导航/输入框、独立滚动、搜索聚焦和等高筛选；核对筛选同时影响图上标记与事件表。
5. 模拟数据源失败，检查错误披露、证据缺口和恢复；在比较报告修改权重并通过“重算此配置”检查关联新版本。
6. 检查四种产物、Excel 重算、来源回链与凭据隔离。

这是一份验收建议，不是全部已执行的结果。实际完成范围及历史阶段见 [验证记录](validation.md)。
