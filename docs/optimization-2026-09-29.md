# 事件关联、覆盖与敏感性设计

本文说明事件关联、需求覆盖和资产配置敏感性的实现取舍。当前完整验收见 [运行验收](final-evaluation.md)，工程命令与证据索引见 [验证记录](validation.md)。

## 事件与行情关联

原先用同标的、自然日正负三天关联，可能遗漏跨周末反应，也允许后发布的信息挂到较早的行情。

现在以行情实际日线序号计算，候选事件必须已公开，关联窗口为事件对齐交易日之后的 0–5 根日线。保存 `lag_bars`、`relation`、来源 ID 与判断依据。延迟候选关联在异动日显示菱形，点击进入对应事件证据，发布日仍保留事件标记。候选关联只说明时序与标的吻合，不能据此证明触发关系。

事件的日期和报道的发布时间分别处理。几天后的回顾文章不能把事件窗口推迟到报道当天；没有同日精确时刻时保留日期精度与不确定性。

## 需求覆盖与有界补查

主管把用户点名要求保存为 `required_events`；提取器逐项声明事件实际满足的要求，核验器检查该声明，论文公开不能冒充模型首次发布。`event_scope=focused` 限制单事件任务，不要求额外凑齐其他年份或事件。

新增独立质量清单：点名要求、超过半年的年度区间、主要五个行情变化是否调查、行情区间覆盖。调查可以没有找到可信解释，但不得伪造事件来增加匹配率。公司名称检索与代码检索同样有效，窄时间窗和调查目标都保留。

事实核验或覆盖不满足时进入补查，最多两轮。首轮预留 18 次搜索、30 次读取；每轮修复最多追加 8/10，总上限 34/50，重启不重置预算。到达上限后仍有缺口则交付 `partial`。报告、Excel Coverage 与 PPT 明确展示，执行结束不等于要求全部满足。

## 核验质量与真实评估

数值工具区分严格相等与显示精度相容，避免把正确的百分比舍入误报为错误。Prompt 明确前收盘到当收盘是一日收益、盘后公告对齐下一交易日、限定为盘中的数据不必改写为收盘值。

`tools/evaluate_research_quality.py` 从自然语言启动完整联网研究，原始 Bundle 与运行轨迹保存到独立运行目录。检查点名要求、范围、参数、引用、数值及补查结果，不人工改写结果来让评估通过。该阶段记录保留在 `evals/research-quality-latest.json`；文字核验增强后的完整验收使用 `tools/evaluate_text_research.py`。

这些是自动验收条件，不等于独立人工核对后的事实准确率。原有 22/22 仅是任务解析评估，两者分开记录。

## 配置敏感性

比较场景新增事先固定的一次改变一个参数的情景：成本 0/10/25/50 bps，持有/月/季/年再平衡，两资产第一资产 20%/50%/80% 权重，以及样本足够时的前后半段。保留用户原始配置为基线，不从中选择所谓最优策略。

所有情景使用相同的下一可交易开盘执行引擎，报告年化收益、回撤、波动和累计费用。HTML 可按维度筛选；Excel Sensitivity 是注明口径的结果快照，蓝色输入格仍驱动原有 MonthlyCalc 公式重算。Word/PPT 同步展示敏感性结果与适用限制。分段分析不是样本外检验。

## 工程和交付

覆盖检查与敏感性分析拆成独立 Python 模块；前端使用独立组件，图表引擎按需加载并分包，离线报告仍是无需联网的单文件。GitHub Actions 在 Ubuntu 执行自动化门禁，Windows 和 Docker 路径的实机范围另行记录。

`tools/package_delivery.py` 仅收集白名单源码、锁文件、文档、评估和样例，排除 `.env`、运行缓存和安装目录；扫描配置密钥及 Office 压缩内容，生成 ZIP 与 SHA-256。源码及关键阶段提交保存在 [GitHub 私有仓库](https://github.com/coetzeexu/evidence-research-agent)。

文件结构、Excel 独立重算、Office 排版与浏览器交互分别记录检查范围。方法页排版修复保留原检查证据；后续功能变化由对应运行重新验证，不能直接继承旧视觉结果。
