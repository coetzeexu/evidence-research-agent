# Agent loop 与工程交付复核

本轮按用户要求区分流程缺陷、模型表现与偶发故障：修复可复现的工程问题，模型表现只保留为评估观察，不列为工程待办或交付阻塞；没有证据时不把重复现象解释为偶发。

## partial 的含义及五次原因

`complete`：发布门禁认为必答问题都已回答，数据/调查覆盖达标。`partial`：已有通过门禁的内容，但至少一个必答问题未完成，只发布这部分及缺口。`failed`：没有可发布正文。状态与导出文件是否存在分开，也不是可信度百分比。

| 原运行 | 未完整发布的部分 | 直接触发原因 |
| --- | --- | --- |
| NVDA `a37b23dee36946f0` | 2025-01-27 下跌 | “最高”未被转录为可计算关系 |
| NVDA `1a40cf5889a445ec` | Blackwell、DeepSeek 与下跌分析 | 关系数学上成立，但核验器改写引文，逐字检查失败 |
| GLD/BTC `c3901fcf59574029` | 压力期、通胀、部分敏感性 | 核验器将占位符替换成数字或改写比较句，引文失配 |
| GLD/BTC `bb46e598f9bf4551` | 压力期、分段敏感性 | 关系运算符/参数错误，以及遗漏比较句 |
| GLD/ETH `c5908f8bc20a485a` | 敏感性 | “居中”未被转录为可计算关系 |

五次均不是超时或数据服务崩溃，实际耗时均少于八分钟。此前将它们统称“证据不足”不够准确：这里多数是核验协议未完成，不能推断没有数据。

## 三类现象的归因

| 现象 | 证据与归因 | 本轮处置 |
| --- | --- | --- |
| CPI 机制否定、提前定价等夸大推断漏检 | 错误句已进入独立语义核验上下文，规则明确禁止，返回仍未指出问题；主要是本配置模型的语义判断表现。多次出现，不能称为一次偶发；未做跨模型对照，不能断言换模型必定解决 | 作为历史评估观察保留；按用户要求不继续调模型、不追加工程待办 |
| 正确数值关系被拒绝 | 模型转录错误是触发因素；流程却把核验器的错误送回作者重写正文，且依赖模型逐字复写原句，是可重复的 loop / 接口缺陷 | 增加一次有预算的核验器专用修复；选择程序生成的片段 ID，原句由程序回填，数学关系重新执行。正文和语义判定不可更改 |
| 缺少论文日期仍标 complete | `research-draft-1.json` 已声明缺口；完成判定未读取 `draft.gaps`，`apply_narrative_patch()` 又未保留缺口。后续只信 `answered=true` | 跨轮持久保留缺口；关闭需明确 gap ID、已批准结论及可定位回答片段。开放缺口触发定向调查，复用/恢复不能清空它 |

工程修复处理状态传递和核验协议，不宣称程序可以独立判断所有自然语言语义。片段定位、指标存在、数学运算和缺口关闭记录由程序检查；一段证据是否足够支持复杂推断仍依赖语义判断。

## 定向验证

从五次 partial 各固定一个原始失败结论，保留正文、指标和原核验记录。第一次仅重试转录仍未通过，记录在 `loop-repair-validation-before-spans.json`；改用片段 ID 后，同样五条均通过数值关系复验。全程正文及原有语义 verdict 不变，每条一次模型调用，不检索、不重新研究、不改写原八次结果。

[固定失败夹具](../evals/loop-repair-cases.json) · [最终定向重放](../evals/loop-repair-validation.json)。这是五条原失败片段通过，不等于原先五份完整研究被重新认证为 complete。

自动回归覆盖：正确转录恢复、unsupported 不被升级、修复超时保留拒绝、缺口跨补丁与恢复保留、仅有 answered=true 不能完成、关闭缺口必须引用已批准且可定位的答案。模型表现观察与确定性工程回归分开记录。

## 对 Gemini 建议的取舍

1. **采纳 Schema 同步与重导出。** 补齐 canonical Bundle，`research replay` 成功导出后同步样例快照，验证原文件、内嵌 HTML、JSON 与 manifest 的一致性。不削弱 `verify_samples.py` 的断言。离线 replay 不执行研究，旧样例 `research=null`、正文核验状态 `unassessed`，旧计算版本保留；不能生成虚假的核验正文。实际新正文样例仍在 `evals/text-research/`。
2. **采纳 Git 与真实 CI。** 原项目已有 Actions 配置但没有 Git 仓库；建立用户 GitHub 私有仓库，按真实工作阶段提交，不编造历史。采用 Ubuntu 的快速离线门禁，构建在 pytest 前，确保导出相关测试实际执行；pytest、Vitest、静态检查、构建与 verify_samples 自动运行。跨平台启动脚本保留，本轮不把 Linux CI 说成三平台实测。
3. **采纳能力接口，暂不接入商业服务。** 通过 `DataProviderInterface` 组合行情、资讯与宏观接口，提供依赖注入和服务端 entry point 配置。公共适配器继续工作；商业厂商需要真实许可与口径适配，不能仅靠统一方法名宣称已接入。见 [数据源扩展](data-providers.md)。

本轮不再次执行八次完整模型研究，不改模型，不做浏览器或图片检查。用户本次明确提出重导出样例，因此执行 HTML/Office 的代码生成及结构验证；不会将生成的图片加载到 Codex 上下文。
