# Agent 闭环与工程复核

本次工程强化重点是核验协议、状态传递、Schema 一致性和可扩展边界。归因依据保存的输入、草稿、工具结果和核验记录，区分可复现流程缺陷与模型语义判断；不把所有输出波动归为程序错误，也不在缺乏证据时解释为偶发。

## 数值关系核验

正文数字引用确定性指标。数值关系还需要检查“高于”“为负”“居中”等文字与指标是否一致。原协议要求模型逐字复写比较句，模型可能改写占位符或句子，导致引用定位失败；若将这种错误交给作者重写，会放大为无效修复循环。

当前流程由程序切分并标记片段，核验器选择片段 ID、运算符和指标参数；程序回填原句并执行数学关系。转录问题最多进入一次有预算的专用修复，修复不能改正文、事实判定或已批准结论。真实 unsupported 判定仍阻止发布。

指标占位符中的字面 `metric_id:` 前缀只在剩余 ID 精确存在时规范化，保留修复记录；不猜测近似指标。绝对幅度比较使用独立 `abs_*` 运算，带符号比较保留原运算，避免将负回撤数值大小和回撤深度混用。正负混合、等幅、序列顺序与反例均有程序回归。

冻结的五个原始片段均通过修复后的数值关系复验，正文保持不变。对应[夹具](../evals/loop-repair-cases.json)与[定向重放](../evals/loop-repair-validation.json)可复核；完整研究另按固定问题运行，见[运行验收](final-evaluation.md)。

## 缺口与完成状态

初稿的显式缺口保存在研究记录中，跨补丁和恢复保留。关闭缺口必须给出 gap ID、已批准结论及可定位回答，不能只依赖 `answered=true`。未关闭缺口可触发定向调查，有限结论与事实缺失分别处理。

新增独立 `question-review` 阶段，在结论门禁之后只依据已核验段落核对原请求与 acceptance。它不改写 claim verdict，也不将被拒绝内容当作潜在答案。明确事实仍缺失时继续阻断完成；已有有限实证回答、但未证明因果或机制时，按研究边界处理，不自动增加用户未要求的回归或额外数据条件。关闭这类额外方法缺口仍需逐条给出可定位的回答与理由。

问题完成依据已核验内容对必答要求的覆盖，不因同一问题下另一个被拒绝的可选段落一票否决；被拒内容始终不发布。核心事实未被回答或显式缺口未关闭仍为 `partial`。额外问题按相同用户原话精确去重，不合并不同事实要求。完成度核验允许一次协议重试，空对象不能充当通过结果。

| 研究状态     | 含义                                                   |
| ------------ | ------------------------------------------------------ |
| `complete`   | 必答问题已回答，数据与调查覆盖满足发布条件             |
| `partial`    | 有可发布内容，仍有明确的必答缺口；发布已核验部分和缺口 |
| `failed`     | 没有可发布正文                                         |
| `unassessed` | 旧快照缺少新正文核验记录                               |

这些状态表示研究完成程度，与程序运行是否成功、文件是否生成分开，也不是可信度百分比。

自动回归覆盖转录恢复、unsupported 不被升级、超时保留拒绝、缺口跨轮保留、单独 answered 声明不能完成，以及关闭缺口的依据校验。语义核验检查原文是否支持措辞；程序保证引用、计算和状态约束，二者职责明确。

## 恢复与精确补丁

进入正文流程时，旧问题清单的状态、结论 ID 和状态缺口重新初始化；只有同输入哈希的已保存 assessment 可以恢复已完成状态。回归验证在旧问题均为 answered、但没有对应 assessment 时，本轮已核验段落仍能保存并发布，不会被旧完成数错误淘汰。

精确补丁的 `old` 片段不匹配时，同一修复轮次最多重试一次。重试接收原补丁与明确错误，失败编辑和原因同时保存。再次无效或调用中断时保留已有可发布结果，不发布错误草稿。测试分别检查二次改正完成和连续两次失败的调用数、正文轮次与恢复结果。

当 `old` 精确匹配且 `old == new` 时跳过该无改动项，继续应用同补丁内的有效修改；这不增加核验证书，失败条目仍逐条重审。正文阶段不宣称文件已生成，文件状态以导出后的真实清单为准。

这些修改使用正文核验协议 `1.3`，计算方法仍为 `2026.09.4`。开发快照复验与完整端到端验收分别记录，运行结果见[运行验收](final-evaluation.md)。

## Schema 与样例闭环

`research replay` 规范化 canonical Bundle、迁移 Schema、重导出文件，再保存一致快照。`verify_samples.py` 同时检查 Bundle、HTML 内嵌数据、JSON、Office 结构与 manifest，不通过削弱断言解决版本不一致。

离线 replay 不执行研究，历史样例保留 `research=null` / `unassessed` 及原计算版本。迁移记录与真实联网研究分别保存，避免把结构兼容等同于新的内容核验。

## 阶段收尾的用户体验修复

离线报告的 React 依赖曾保留 `process.env.NODE_ENV`，导致下载后打开空白。报告构建显式替换该值，实际编译产物测试禁止残留 Node 环境读取；两套样例重新导出，并用本机浏览器打开 `file://` 文件验证。

“需求覆盖检查”是研究范围核对，不是结论置信度评分。按用户最终反馈移除各 tab 公用的核对面板，保留正文中的具体缺口、局限和来源引用。过程中的失败尝试留在对应步骤，不在结果尾部叠加失败计数；方法、数据口径和排除记录收在可展开说明中。真实未回答问题仍逐项列出，底层 `partial` 不改成 `complete`。

本机来源诊断复现了 HTTP 403、404、连接超时和非公网 DNS 地址被安全检查拒绝。重复读取无法修复访问限制、失效 URL 或安全拒绝，Agent 应改用可读取的来源；网页出现过读取失败不等于最终结论没有依据。诊断和实际浏览器证据保存在本轮验收记录中。

按用户阶段收尾要求，本轮聚焦执行中断、文件不可用和展示歧义；模型措辞及推断差异保留为效果评估观察，不继续扩展为新的工程修复任务。

来源阅读仅对超时、连接中断、429 和 500/502/503/504 增加一次自动重试，等待一秒；403、404、安全拒绝和正文不足不重试。每次重试仍经过域名解析、公开地址校验、IP 固定与重定向检查。全局研究截止时间仍有效，无法以增加重试保障所有站点可读。新增八项传输用例验证恢复、上限、拒绝访问与安全边界。
