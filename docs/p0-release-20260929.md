# P0：指标契约与可验证交付

本轮从 80 分评估中收敛两个 P0：指标含义/单位/发布边界，以及 ZIP 与源码的一致性。目标是消除可以确定复现的错误与交付版本漂移；不把旧版内容复核 3/8 改写为新版通过，也不凭单元测试宣布达到 90 分。

## P0-1：显式指标契约

根因：指标目录把没有声明单位的所有数值默认作为百分比，导致年化周期 `12` 输出为 `1200%`。

- 每种数值有显式单位、中文名称和 meaning；未知数值字段中止目录构造，不猜测百分比。
- 分别提供价格/净值观测数、相邻收益观测数、CPI 有效配对样本数。年化周期与再平衡间隔分别定义。
- 计数必须是非负整数，指标不接受 NaN/Infinity；标题和正文使用同一占位符格式化。
- 发布检查拒绝占位符后重复/错配的单位及未绑定的样本数。
- 多数使用严格超过一半的程序断言；方向一致核对每个被引用的对应事件窗口；描述性 CPI 指标不能推出机制成立或不成立。
- 正文核验协议提升至 1.4，参与恢复输入哈希。旧协议的核验结果不能自动授权新正文。

方法仍为 2026.09.4：没有修改价格、收益、回测引擎或历史原始数据。历史报告不静默重写，保留原错误作为回归证据。

验证采用先失败再修复：最初 9 项契约测试中 8 项失败；修复后契约与发布边界测试 26 项通过，其中直接读取旧 Blackwell 错误输出，确认旧 reviewer 的 supported 不能继续放行。完整后端回归为 282 项。

## P0-2：发布一致性

`tools/package_delivery.py` 保留允许列表、凭据检查、Office 内部检查和启动权限，新增：

- 每个文件的 SHA-256 清单、Git 提交/工作区状态和整个交付树的摘要。
- ZIP 内实际成员集合必须与清单相同，检查重复成员、危险路径、私有状态与文件哈希。
- 将清单与当前源码重新比对，源码新增、删除、修改均会拒绝旧 ZIP。
- 先写临时 ZIP 并通过核验，才原子替换正式交付包；失败不破坏旧包。
- CI 构建后实际打包并重新校验。

```bash
uv run python tools/package_delivery.py --output ../research-agent-delivery.zip
uv run python tools/package_delivery.py --verify ../research-agent-delivery.zip
uv run python tools/check_delivery.py \
  --archive ../research-agent-delivery.zip \
  --work-dir ../../work/release-check-new \
  --output ../release-check.json
```

清洁检查使用全新解压目录，清除模型凭据，从 `run.sh` 安装依赖和构建，验证 HTTP 健康检查、两个样例、八个文件下载哈希、无密钥时的新研究拒绝，以及解压目录中的后端/前端回归。不会打开浏览器。首次安装依赖需要联网。

最终 ZIP 的校验报告放在 ZIP 外部，避免“报告写入包内 → 包哈希改变 → 报告再次过期”的自引用问题。源码、包内清单、外部校验记录各自有明确作用。

## 验证边界

第一轮真实研究记录在 `evals/text-research/P0ContractGold20260929/` 与 `P0ContractNVDA20260929/`。黄金首轮自动通过，但事后阅读发现“最低”被转录为“递增”，保留失败记录并新增回归。第二轮补上原句与运算关系绑定，冻结后重跑，记录在 `P0FinalGold20260929/` 与 `P0FinalNVDA20260929/`。两次最终运行自动验收均通过，但事后正文复核均不通过（0/2），详见 `evals/p0-live-validation-20260929.json`。黄金报告仍有未经检验的少数月份敏感推断，并缺少频率敏感性的实际回答；NVDA 报告未计算 beta 却称高贝塔，且 B100 核实缺口未披露。单位与计数抽查通过，但不足以证明整体达到 90 分。原始输出不改写，另存内容复核；不能继承上一版八次验收结果。

历史 NVDA/黄金样例继续保留原数据、方法版本和 `unassessed` 标识。它们用于离线可视化/Office 演示，不冒充本轮新模型研究。Windows/Docker 和完整视觉验收不属于本轮新增验证。候选包已在全新目录完成安装、构建、启动、八个下载哈希与解压后 282/28 项回归；正式包冻结后再执行同一脚本，最终结果以包外 `release-check-20260929.json` 为准。

下一轮优先级：将“完整”判定落到子要求与已接受正文的对应证据，阻止删掉失败段落后仍宣称完整；再对 beta、影响点、机制归因等未计算属性建立明确证据要求。两项均需新增真实运行复核，不能只提高自动通过率。

## AI 开发过程

Codex 对照真实输出定位默认单位错误，先写失败回归，再实现显式契约、发布边界与交付核验脚本。用户确定冲刺目标并授权两个 P0；工程选择是优先做确定性约束和可复现发布，而不扩大业务范围。所有回归、联网评估和清洁启动保留实际结果；未调用开发子 Agent 或浏览器。
